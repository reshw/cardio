## 이슈 1: 발레 운동 종목 추가 요청

### 요청
이지희 대리님이 "발레"를 운동 종목으로 추가해달라고 요청.

### 논의 내용
- 1차 답변: 지금도 "기타운동"에 자유 입력 가능 (이미 있는 기능)
- 문제 제기: 발레처럼 특이한 종목은 **클럽원들에게 공개되는 게 부담스러움** ("발레로 만천하에 공유하고싶으세요?")
- 절충안: **본인이 기록할 땐 "발레"로 저장하되, 남에게는 "기타운동"으로 보이게 처리** → 가능할 듯
- 운동량 산정 방식 논의:
  - 기타운동은 현재 "분" 단위, `n분당 m점` 방식으로 계산됨
  - 요가는 이미 종목으로 있음(칼로리 계산방식이 발레와 비슷할 것으로 추정)
  - 최종 아이디어: **발레와 비슷한 기존 종목(요가 등)의 산정 방식을 그대로 가져다 쓰는 방식** → 가능할 듯으로 합의
- 부가 요청: "자기가 하는 운동이 있냐 없냐가 사기 팍 올라감" → 종목을 넓게 지원하되:
  - **메인/클럽 화면에는 지금처럼 핵심 종목만** 노출
  - 전체 종목 목록은 **"기록" 탭에서 본인 기록만 쭉 보이는 걸로 이미 충족** (클럽 탭 = 다같이 보는 곳, 기록 탭 = 본인 전용) — 별도 즐겨찾기/편집 UI는 불필요하다는 쪽으로 정리됨

### 액션 아이템
- [ ] "발레" 운동 종목 추가 — 산정 방식은 요가 등 유사 종목 계수 재사용
- [ ] 신규/특이 종목은 클럽 피드 등 타인에게 노출될 때 "기타운동"으로 라벨 대체 표시하는 처리 검토 (본인 기록엔 원래 종목명 유지)
- [ ] 어떤 종목들을 "타인에게는 기타운동으로 표시" 대상으로 묶을지 기준 정하기 (발레만? 비주류 종목 전체?)

## 이슈 2: 테마/디자인 커스터마이징 → 프리셋 팔레트 개발은 검토, 완전 자유 커스텀은 비추

### 요청
이지희 대리님이 캘린더 앱들처럼 테마 색깔/이모티콘 바꾸는 앱꾸미기 기능 요청.

### 결정 (업데이트, 260810)
- **완전 자유 컬러 선택(컬러피커)은 여전히 비추** — 브랜드 이미지 우려("거지같은 배색으로 도배한 앱") + [docs/design-guide_color-system.md](design-guide_color-system.md) §5에 이미 같은 결론 기록됨(`--primary-color`가 배경/글자 양쪽에 쓰여서 사용자가 밝은 색 고르면 대비 사고 남)
- **다만 이미 라이트/다크 두 테마를 `[data-theme]` + CSS 변수 토큰 구조로 지원 중이라, 미리 검증한 팔레트 프리셋 몇 개(예: 라이트/다크 외 2~3종) 추가하는 정도는 괜찮다는 쪽으로 정리**
  - 디자인 가이드 §5 "새 테마를 추가하려면" 절차 그대로 따르면 됨: `App.css`에 `[data-theme='이름']` 블록 추가 → `useTheme.ts` Theme 타입/분기 추가 → `index.html` FOUC 스크립트 동기화 → More.tsx 설정 UI를 토글→선택형으로 변경
  - 프리셋마다 `--on-accent` 대비값은 사전 검증 필수 (컬러피커처럼 사용자가 직접 배색을 골라서 사고 나는 구조가 아니라, 우리가 미리 검증한 세트만 제공하는 거라 리스크 없음)

### 액션 아이템
- [ ] 프리셋 팔레트 몇 개(2~3종) 디자인 시안 뽑기 — 라이트/다크 톤 유지하면서 포인트 컬러만 다르게
- [ ] 프리셋별 `--on-accent` 등 대비 검증 (design-guide_color-system.md §4 감사 스크립트 활용)
- [ ] More.tsx 테마 설정 UI를 토글 → 프리셋 선택형(라디오/스와치)으로 변경
- [ ] (계속 비추) 자유 컬러피커는 진행 안 함

## 이슈 3: 운동 장소/GPS 경로 기록

### 요청
- 1차: 운동 장소/루틴을 km수 말고 기록할 수 있는지
- 구체화: 러닝 GPS 경로를 자동으로 등록해서 위치 표시 + km수와 같이 보여주면 좋겠다는 제안
- "본인만 볼 수 있게(온오프 토글)" 절충안도 제시됨

### 1차 결정 (대화 당시): 보류
- 장소 텍스트 메모 수준은 지금도 수기로 가능 (기존 메모 필드로 충분)
- GPS 자동 위치기록은 **개인정보 보관 부담 + 유출사고 리스크로 보류** ("유출사고나면 파산날껄")
- "본인만 볼 수 있게" 해도 서버에는 결국 위치 데이터가 쌓이는 구조라 리스크는 동일 → 온오프 토글로도 해소 안 됨
- 그 자리에서는 **유료 앱으로 전환되면 그때 재검토**로 정리 ("나중에 유료어플 되면 만들어주셈")

### 업데이트 (260810) — "GPS 자체 수집"이 아니라 "이미 있는 Strava 경로 데이터 활용" 관점으로 재검토
양석환이 지적: **Strava 연동 워크아웃은 이미 경로 데이터를 서버에 저장하고 있음.**
- `api/webhooks/strava.ts` — Strava activity 동기화 시 `activity.map.summary_polyline`을 `polylineToGeoJson()`으로 GeoJSON `LineString`으로 변환해 `workouts.route` 컬럼에 저장 중 (create/update 둘 다)
- `api/_strava-shared.ts` — 이미 이 polyline을 디코딩해서(`decodePolyline`) 좌표 정규화 후 SVG path로 그리는 `buildRouteData`/`buildRouteCardSvg`가 있음 → 현재는 **카카오 공유용 운동 카드 이미지**(`generateStravaCard`)에 경로 모양을 얇은 라인으로 그려넣는 용도로만 씀. 실좌표 기반 지도가 아니라 bounding box에 맞춰 스케일된 "모양"만 그리는 방식.

즉 "새로 GPS를 수집해서 서버에 쌓아야 하나"의 문제가 아니라, **Strava 소스 워크아웃에 한해서는 이미 쌓여있는 `route` 데이터를 GPX로 변환하거나 실제 지도(타일) 위에 올려서 보여주기만 하면 되는** 훨씬 작은 작업일 수 있음.

- 이 경우 원래 우려(자체 GPS 트래킹 신규 구축 + 서버 부담 + 유출 리스크)는 **Strava가 이미 그 데이터를 우리 서버에 넘겨주고 있는 상황이라 성격이 다름** — 신규 수집이 아니라 이미 저장된 데이터의 노출 범위 문제로 좁아짐. 다만 여전히 위치 데이터라 노출 범위(본인만/클럽 공개 여부)는 정할 필요 있음
- **Apple Health 소스도 가능성 있음** — `workouts.route`는 Strava 전용 컬럼이 아니라 범용 `jsonb`(`supabase/migrations/20260703000001_add_route_column.sql`). Apple HealthKit의 `HKWorkoutRoute`는 Garmin Connect 등 GPS 워치 앱에서 기록해 Apple Health로 동기화된 운동이면 경로 데이터를 포함하는 경우가 많음 → 스키마상으론 Apple Health 쪽도 같은 `route` 컬럼에 채워 넣을 수 있음
  - 단, **iOS 네이티브 동기화 코드가 실제로 `HKWorkoutRoute`를 가져와서 쓰고 있는지는 이 웹 레포에서 확인 불가** — 그 로직은 iOS(`app`) 저장소 소관. `app` 에이전트에게 확인 필요
- **Android도 동일한 결이 있음** — `native-bridge.d.ts`의 `openHealthSync`가 iOS/Android 공통으로 "Health Connect/Apple Health 화면을 연다"고 돼있는 걸 보면 Android는 Google **Health Connect**로 건강 데이터를 동기화하는 구조. Health Connect도 `ExerciseRoute`(GPS 좌표 시계열)를 러닝 등 운동 레코드에 포함할 수 있어서, Garmin Connect/Strava 앱 등에서 기록해 Health Connect로 동기화된 운동이면 Apple Health와 같은 경우가 성립함
  - 이것도 실제로 `and`(Android) 네이티브 동기화 코드가 `ExerciseRoute`를 가져오는지 확인 필요
- **수동 입력 워크아웃은 route 데이터가 없음** (당연히 근거 데이터 자체가 없음). 순수 자체 GPS 자동 트래킹(앱이 직접 위치 수집하는 기능)은 여전히 기존 결론(보류, 유료화 이후) 유지 — 이건 Strava/Apple Health처럼 "이미 받아온 데이터 활용"이 아니라 신규 수집이라 리스크 성격이 다름

### 참고
- 대화 중 "사진 2장" 언급 있었으나 카톡 이미지 첨부라 텍스트 로그에는 내용 없음 — 필요하면 원본 대화방에서 재확인 필요
