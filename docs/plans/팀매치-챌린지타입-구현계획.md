## 1. 검토 결론

### Q1. 챌린지의 한 종류로 특정 기간 팀대항전 운영이 가능한가? → **가능**

- `challenges` 테이블이 이미 확장 가능한 구조:
  - `start_date` / `end_date`가 임의 기간 지원 (월 단위 강제 아님 → "하반기" 같은 장기 매치 가능)
  - `meta_data jsonb`, `rules jsonb` 컬럼이 이미 존재 (팀전 설정 저장 가능)
  - `goal_metric` / `goal_value`는 이미 NULL 허용으로 완화됨 (20260428 마이그레이션) → 개인 목표 없는 타입 수용 가능
- 팀대항전.md에서 이미 "챌린지와 같은 레벨의 이벤트 타입" 방향으로 기획 확정된 상태
- 기존 `challenge_participants`(개인별 목표 선언 모델)와는 데이터 모양이 다르므로, **팀/팀원 테이블을 별도로 추가**하고 `challenges`에 타입 컬럼만 얹는 방식이 맞음

### Q2. 테넌트(클럽)별 적용 가능한가? → **가능, 사실상 공짜**

- `challenges`는 이미 `scope='club'` + `club_id NOT NULL` 제약으로 클럽 스코프 강제 (`check_club_scope`)
- 마일리지 집계 원천인 `club_workout_mileage`가 **클럽별 계수(`club_mileage_configs`)로 계산된 클럽별 스냅샷** → 팀 집계도 자동으로 클럽별 격리
- RLS 패턴(클럽원 조회 / 매니저·부매니저 관리)이 `challenge_participants`, `club_mileage_configs`에 이미 확립되어 있어 그대로 복제하면 됨
- 같은 클럽 내 대결이므로 계수 동일 → 직접 비교 가능 (팀대항전.md 확정사항과 일치)

### PDF에서 "DB 활용으로 이미 가능한 것" 검증

| PDF 주장 | 검증 결과 |
|---|---|
| 지그재그(스네이크) 자동 배정 | ✅ `club_workout_mileage`에 `workout_date`가 있어 최근 3개월 개인 평균 산출 가능 |
| 실시간 팀별 평균 마일리지 | ✅ 매치가 단일 월로 확정되어 기존 월 집계 RPC `get_club_mileage_summary` 그대로 재사용 |
| 개인 성장률(아차상) | ✅ 매치 기간 평균 vs 직전 3개월 평균, 같은 테이블에서 계산 가능 |
| MVP (명전 제외) | ✅ `hall_of_fame` 테이블 존재, 제외 필터 가능 |

## 3. DB 설계

### 3-1. challenges 타입 컬럼 추가

```sql
ALTER TABLE public.challenges
  ADD COLUMN challenge_type text NOT NULL DEFAULT 'personal_goal'
  CHECK (challenge_type IN ('personal_goal', 'team_match'));
```

기존 챌린지는 전부 `personal_goal`로 유지 — 기존 UI/서비스 영향 없음.

팀매치 설정은 `meta_data`에 저장:

```json
{
  "team_match": {
    "metric": "avg_mileage",          // 1인당 평균 마일리지 (고정)
    "baseline_months": 3,             // 드래프트/성장률 기준 개월수
    "avg_denominator": "recorded"     // 평균 분모: recorded(기록자만) | all(전원)
  }
}
```

> **매치 기간은 단일 월로 확정** (2026-07-13 결정). 다개월 매치 없음.

### 3-2. 팀 / 팀원 테이블 (신규)

```sql
CREATE TABLE public.challenge_teams (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  challenge_id  uuid NOT NULL REFERENCES public.challenges(id) ON DELETE CASCADE,
  name          text NOT NULL,
  color         text NOT NULL,            -- 랭킹 표식/차트 색
  sort_order    int  NOT NULL DEFAULT 0,
  created_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE public.challenge_team_members (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  team_id       uuid NOT NULL REFERENCES public.challenge_teams(id) ON DELETE CASCADE,
  challenge_id  uuid NOT NULL REFERENCES public.challenges(id) ON DELETE CASCADE,
  user_id       uuid NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  is_captain    boolean NOT NULL DEFAULT false,
  joined_via    text NOT NULL DEFAULT 'auto' CHECK (joined_via IN ('auto', 'self', 'admin')),
  created_at    timestamptz NOT NULL DEFAULT now(),
  UNIQUE (challenge_id, user_id)          -- 한 매치에 한 팀만
);
```

RLS (기존 패턴 복제):
- SELECT: 해당 챌린지의 클럽 멤버
- INSERT(자율 선택): `user_id = auth.uid()` AND 본인이 해당 클럽 멤버 AND 아직 미배정
- INSERT/UPDATE/DELETE(배정·조정): 매니저/부매니저

### 3-3. 집계 — 신규 RPC 불필요

매치가 단일 월이므로 기존 `get_club_mileage_summary(club_id, year, month)` 재사용:

- **팀 순위**: 매치 월 1회 호출 → `challenge_team_members`로 조인해 클라이언트에서 팀 그룹핑·평균
- **드래프트 기준(최근 3개월)**: 월별 3회 호출 후 합산 — 관리자가 팀 구성 시 1회성 실행이라 부담 없음
- **성장률(아차상)**: 동일하게 직전 3개월 월별 호출 합산
- 스냅샷 미생성 월 방어는 기존 `getClubRanking`의 자동 재계산 패턴 그대로 사용

## 4. 프론트엔드 설계

### 4-1. 생성 플로우 — ChallengeCreateModal 확장

- 타입 선택: `개인 목표 챌린지`(기존) / `팀 대항전`(신규)
- 팀 대항전 선택 시: 팀 수(2~4), 팀 이름·색상(사신수 프리셋 기본 제공, §4-6), 기간(단일 월), 평균 분모 옵션
- 생성 직후 → 팀 배정 화면으로 유도

### 4-2. 팀 배정 관리 모달 (신규, 매니저 전용)

1. **자동 드래프트 버튼**: 최근 3개월 `get_club_mileage_summary_range` → 평균 내림차순 정렬 → 스네이크(1→2→3→4→4→3→2→1) 배정
2. **수동 조정**: 멤버 팀 간 이동 (PDF: "팀평균이 너무 차이나는 경우 운영진이 선수 조정")
3. 팀장 지정(선택), 팀별 예상 평균 실시간 표시
4. 무기록자는 미배정 풀에 남김 → 본인이 자율 선택

### 4-3. 팀매치 카드 — ClubChallengeSection 내 분기 렌더

`challenge_type === 'team_match'`이면 개인 목표 카드 대신:

- **팀 순위 보드**: 팀별 1인당 평균 마일리지 막대 + 순위, 팀 색상
- **내 팀 / 내 기여도**: 내 마일리지, 팀 내 순위
- **미배정 상태면**: 팀 라인업 미리보기 + "팀 선택하기" 버튼 (PDF의 자율 선택)
- 팀 상세 펼침: 팀원별 기여 리스트

### 4-4. 마일리지 랭킹 팀 색상 표식 (PDF "개발할 것" 1)

- Club.tsx 마일리지 랭킹 탭에서, **진행 중인 team_match가 있으면** `challenge_team_members` 조회 → 이름 옆 팀 색상 점/뱃지
- 매치 없으면 아무것도 안 보임 (기존 챌린지 섹션과 동일한 "있으면 표시" 철학)

### 4-5. 결과/시상 화면 (매치 종료 후)

- 우승팀 (1인당 평균 1위)
- MVP: 패배 팀 소속 중 개인 마일리지 최고 (hall_of_fame 명전 제외)
- 아차상: (매치 기간 일평균 ÷ 직전 3개월 일평균) 성장률 상위 — 무기록→기록자는 분모 0 처리 규칙 필요
- 기존 `ChallengeArchiveModal` 흐름에 통합

### 4-6. 축제 연출 디자인 (PDF "개발할 것" 1 — 축제 분위기 연출)

**팀 아이덴티티 — 사신수(四神獸) 프리셋**

| 팀 | 상징 | 컬러 토큰 | 랭킹 표식 |
|---|---|---|---|
| 주작 (홍) | 🐦‍🔥 | `#dc2626` | 붉은 원 뱃지 |
| 백호 (백) | 🐯 | `#f8fafc` + 테두리 `#94a3b8` | 흰 원 + 은회색 테두리 (흰 배경 대비 확보) |
| 청룡 (청) | 🐉 | `#2563eb` | 파란 원 뱃지 |
| 현무 (흑) | 🐢 | `#171717` | 검은 원 뱃지 |

- 팀 이름·이모지·컬러는 `challenge_teams.name/color` + meta로 저장, 프리셋은 생성 모달의 기본값 (관리자 변경 가능)
- 2팀 매치면 주작/백호(홍백전)만 사용, 3팀이면 +청룡, 4팀이면 +현무
- 백호 컬러는 흰 배경 UI 대비 문제가 있으므로 **표식·차트에서는 항상 테두리 동반**, 텍스트 위 배경으로 쓸 땐 `#e2e8f0` 계열로 대체

**연출 요소 (전부 CSS 기반, WebView 안전)**

1. **랭킹 팀 뱃지**: 마일리지 랭킹 이름 옆 팀 컬러 원(또는 이모지) — 매치 기간에만 등장, 랭킹 전체가 "물들어 보이는" 효과가 축제감의 핵심
2. **팀 순위 보드 = 레이스 트랙 연출**: 팀별 1인당 평균을 가로 막대 경주 형태로, 팀 이모지가 막대 끝에서 달리는 모양. 1위 팀 막대에 왕관 👑 + 은은한 pulse 애니메이션
3. **D-day 카운트다운**: 매치 카드 헤더에 "D-7" 강조 칩, 종료 3일 전부터 색상 강조 (역전 알림의 UI 버전 — 푸시 없이도 긴장감)
4. **순위 변동 표시**: 전일 대비 팀 순위 ▲▼ (스냅샷에 workout_date 있어 전일 기준 계산 가능)
5. **결과 발표 카드**: 종료 후 우승팀 컬러 배경 + 우승팀/MVP/아차상 명단 카드. 기존 워크아웃 카드 이미지 생성 인프라를 활용한 공유용 이미지는 후순위 옵션
6. **개인 기여 게이지**: 내 마일리지가 팀 평균에 어디쯤인지 — "팀 평균까지 +12마일" 식 문구로 하위권 동기 부여 (PDF의 '소년가장/버스' 정서)

**연출 제외 (WebView 리스크·과잉)**: confetti 라이브러리, canvas 파티클, backdrop-filter 의존 효과. 애니메이션은 transform/opacity CSS transition만.

## 5. 구현 단계

| 단계 | 내용 | 산출물 |
|---|---|---|
| **1. DB** | challenge_type 컬럼, 팀 2테이블 + RLS | 마이그레이션 2건 |

1~3단계만으로 매치 운영 개시 가능. 4~5는 매치 진행 중에 따라와도 됨.

## 6. 미결 사항 (운영 결정 필요)

1. **평균 분모**: 배정된 전원 vs 기록 있는 사람만
   - 자율 선택 신입이 팀에 들어와 기록을 안 하면 전원-분모 방식에선 팀 평균을 깎음 → "버스 타는 재미"와 충돌. **기록자만 분모(recorded) 권장**, meta_data 옵션으로 열어둠
2. **매치 시작 후 팀 이동/신규 참여 허용 범위**: 자율 선택은 시작 후에도 허용(신입 유입 목적)하되 팀 이동은 매니저만 권장
3. **아차상 자격**: 직전 3개월 무기록자 성장률 계산 불가 → 제외할지, 별도 신인상으로 볼지
4. **역전 알림(D-3)**: 푸시 인프라(device_tokens) 있으나 이번 범위에서 제외 권장 — 추후 단계

## 7. 리스크 / 주의점

- `club_workout_mileage` 스냅샷 누락 월 → 드래프트 기준 3개월 집계 전 월별 재계산 방어 로직 필수
- 집계는 클라이언트 워크아웃 순회가 아니라 기존 `get_club_mileage_summary` RPC(DB 집계) 재사용
- 팀매치 카드/모달은 CLAUDE.md WebView 규칙 준수 (createPortal, vh 금지, `%`/px 사용)
- 기존 개인 챌린지와 동시 운영 가능해야 함 (같은 기간에 두 타입 공존) — challenge_type 분기라 자연 충족
