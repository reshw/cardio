## 읽을 때 주의할 점

- **이수진 요가 20여 건**은 등록간격이 전부 `0s` — 마이크로초까지 같은 트랜잭션에서 들어왔다.
  앱에는 `workouts` 일괄 insert 경로가 없으므로(단건 insert 뿐) 과거 기록 백필 스크립트에서
  같은 세션이 두 번 들어간 것으로 보인다. 사용자가 두 번 누른 게 아니다.
- **교차 소스 3건**(`strava → apple_health`, 이수진 수영 2건·달리기 1건)은 성격이 다르다.
  같은 운동을 스트라바와 애플헬스가 각각 올린 것으로, 레거시 청소가 아니라 **교차 소스 dedup** 문제다.
  보존 규칙상 인증샷이 있는 스트라바 행이 남고 애플헬스 행이 삭제 대상이 됐다 — 결과는 타당하지만,
  근본적으로는 업로드 시점에 막아야 할 건이라 별도 처리가 필요하다.
- 등록간격이 **음수**인 행은 유지 대상이 나중에 등록된 경우다 (보존 규칙이 등록 순서보다
  좋아요·인증샷을 우선하기 때문). 의도된 동작이다.
- `google_health` 는 34건 중 **1건**뿐 (4be8cfc2 사용자, 14초 간격). 안드로이드 HC 레거시 중복은 사실상 없다.
