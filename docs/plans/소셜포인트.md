# 소셜 포인트 시스템 기획

> 작성일: 2026-05-25  
> 원문: `docs/plans/cardio.app.v2.0.md`  
> 위치: v2.0 로드맵 2단계 (루키리그 다음, 보증금제 이전)

---

## 개념

운동 마일리지와 **완전히 별개**의 포인트 트랙.  
"얼마나 뛰었나"가 아닌 "얼마나 커뮤니티에 기여했나"를 측정.  
바쁜 시니어도 뛸 수 없는 날엔 소셜로 기여 가능.

---

## 획득 루트

| 행동 | 점수 | 검증 방식 | 제한 |
|------|------|----------|------|
| 카톡 기록 공유 | +1 | 앱 내 공유 버튼 클릭 자동 | 하루 1회 |
| 신규 회원 추천 | +5 | 신입이 가입 당월 **20마일 + 소셜 5점** 달성 시 자동 적립 | 먹튀 방지 |
| 3인 이상 번개 | +5 | 세 명의 기록 날짜·거리·페이스 일치 확인 | - |
| 운영진 소환 | +15 | 운영진과 함께 인증 (운영진 직접 승인) | 운영진 1인당 1회 |
| 기부금 납입 | +1 | 1만원당 1점, 몸 못 쓰는 날 자본주의 찬스 | - |

> **운영진 소환이 핵심 치트키**: 대장 포함 운영진 4명 × 15점 = 월 최대 60점.  
> 운동 잘 하는 사람이 아니라 "발로 뛰어서 사람 모아온" 사람이 소셜 1위.

---

## 소셜 포디움

- 클럽 마일리지 탭 내 **"소셜"** 서브탭 추가
- 월별 초기화, 역대 소셜 챔피언 명예 기록 보존
- 이달의 소셜 1위 = **"이달의 커넥터"** 시상 (월말 시상 구조에 추가)

---

## 월말 시상 구조 (변경 후)

| 시상 | 기준 |
|------|------|
| 🥇 마일리지 1위 | 당월 마일리지 합산 (현행) |
| 🤝 이달의 커넥터 | 소셜 포인트 1위 → 운영진 추천상 대체 (객관화) |
| 🎓 이달의 졸업자 | 생애 첫 100마일 달성자 전원 |

## 검증 설계 (꼼수 방지)

**신규 추천**: 신입이 당월 활성화(마일리지 + 소셜 조건) 달성 후에만 추천인 포인트 지급. 데려다 놓고 잠수 타면 포인트 없음.

**3인 번개**: 세 명이 같은 날 같은 기록 카드를 올리는 방식. 별도 인증 기능 필요 없이 기존 운동 기록 기반으로 자동 매칭.

**카톡 공유**: 하루 1회 제한 → 단톡방 스팸 방지.

---

## DB 설계 (초안)

```sql
social_points (
  id, club_id, user_id,
  points, action_type, description,
  created_at, year, month
)
```

`action_type`: `'share' | 'referral' | 'meetup' | 'exec_summon' | 'donation'`

월별 합산은 `year + month` 기준으로 집계.

---

## 구현 순서 (MVP)

1. **소셜 포인트 테이블 + 관리자 수동 지급 UI** (운영진 소환, 기부금 등 수동 항목 먼저)
2. **카톡 공유 버튼 → 자동 적립** (기존 공유 기능에 훅 추가)
3. **신규 추천 연동** (가입 플로우에 추천인 입력 + 조건부 자동 지급)
4. **3인 번개 자동 인식** (기록 매칭 로직, 가장 복잡)
5. **소셜 포디움 탭 UI**

> 1→2번만 해도 MVP 운영 가능. 3~4는 2차.

---

## 미결 사항

1. **3인 번개 기준**: 페이스까지 일치해야 하나? 날짜 + 운동 종목만으로도 충분?
2. **소셜 포인트 ↔ 보증금제 연동**: 소셜 포인트로 보증금 차감 완화 가능? 별도 트랙 유지?
3. **운영진 소환 승인 UI**: 운영진이 앱에서 직접 승인? 카톡 캡처 제출?
4. **기부금 실물 연동**: 포인트 수동 입력 (운영진이 확인 후 지급) 방식이 현실적
