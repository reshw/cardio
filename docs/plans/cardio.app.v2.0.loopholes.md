# Cardio App v2.0 기획안 — 제도 허점 항변서 (반론 포함)

> 각 항목은 "왜 뚫리는가 → 반론 → 최종 판정" 순으로 정리.

## 1. 쌍둥이 기록 카드 — 꼼수 방지가 아닌 꼼수 가이드

**기획서 주장**: 날짜·시간·거리·페이스가 소수점까지 일치해야 유효한 3인 번개로 인정.

### 왜 뚫리는가

실제로 함께 뛴 세 사람의 기록은 절대 일치하지 않는다.
가민·애플워치·갤럭시워치는 같은 코스를 달려도 GPS 오차로 거리·페이스가 미세하게 다르다.
세 사람이 카톡으로 "5.00km, 30:00"을 합의하고 각자 집에서 수동 입력하면 시스템이 그대로 통과한다.

### 반론

트랙·수영장처럼 **같은 시설에 함께 있어야만 가능한 운동**은 기록 일치가 의미 없다.
애초에 "같은 시간·같은 장소에 있었다"는 것 자체를 증명하는 것이 목적이라면,
정밀한 자동 검증보다 **운영진이 수상한 번개를 삭제할 수 있는 권한**이 핵심이다.

- 자동 승인(auto-approve) → 운영진 삭제 권한으로 사후 처리
- 소셜 포인트는 어차피 보증금 생존을 위한 보조 수단이지 경쟁의 핵심이 아님
- 엄격한 검증 도구로 커뮤니티를 감시하는 것 자체가 분위기를 해칠 수 있음

**부수 질문**: 소셜 숙제가 너무 많으면 사람들이 질린다. 소셜 포인트를 달성 가능한 수준으로
단순하게 유지하는 것이 더 중요할 수 있음.

### 최종 판정

🟡 **수용 가능** — 휴먼 리스크를 인지하고 감수하는 방향으로 설계.
운영진 삭제 기능만 제대로 만들면 충분.

**개발 필요 사항**: 번개 인증 건별 운영진 삭제 기능 (어드민 UI)

## 2. 3개월 평균 목표 — 의도적 평균 하락 게임

**기획서 주장**: 최근 3개월 평균($M_{3avg}$)의 95%를 생존형 목표로 자동 산출.

### 왜 뚫리는가

평소 100km 뛰던 사람이 2개월을 의도적으로 30km씩만 기록하면
3개월 평균이 53km로 떨어지고, 이후 생존형 목표가 영구적으로 낮아진다.
2개월 벌금(최대 5,000원)을 지불하고 이후 목표를 반토막 내는 게임이 가능하다.

### 반론

이것은 버그가 아니라 **의도된 유연성**이다.

- 사람은 늙는다. 200km 뛰던 고수가 무릎을 다치거나 나이가 들면 페이스가 줄어야 한다.
- "역대 최고 평균"으로 고정하면 부상 회복 중인 회원에게 가혹한 기준이 된다.
- 과한 운동을 억지로 유지하게 만드는 제도는 오히려 건강에 해롭다.
- 2달 적게 뛰어서 벌금 내고 목표를 낮추는 것 자체가 이미 **손실 회피 비용**이다.
  이 제도의 목적은 완주율 제어가 아니라 "완전히 안 뛰는 사람"을 방지하는 것.

### 최종 판정

🟢 **문제 없음** — 롤링 평균은 의도된 설계. 하한선 불필요.

단, 극단적 악용(고의로 0km를 기록해 목표를 0으로 수렴시키는 경우)은
가입 최소 마일리지 요건(예: 방원 자격 유지 조건 5km/월)으로 별도 관리하면 충분.

## 3. 루키 리그 29.9km 정체 — 덜 뛰는 인센티브

**기획서 주장**: 30km 돌파 시 실시간으로 일반 리그 소환 → 양학 방지.

### 왜 뚫리는가

소환 임계값이 공개되어 있으므로 의도적 정체가 발생한다.
월 중순에 28km에 도달한 루키 1위가 나머지 보름을 쉬며 29.8km로 루키 1위를 유지할 수 있다.

### 반론 (현재 미제시)

이 허점은 반론이 약하다. 루키 리그에 별도 상금이나 강력한 보상이 없으면
"29.9km 정체"의 인센티브 자체가 낮아진다. 루키 리그의 목적이
**탈락 방지(이탈 방지)**라면 1위 경쟁보다 "내가 리그에 있다"는 소속감이 더 중요.

### 최종 판정

🟡 **보완 권장** — 루키 리그 1위에게 별도 보상이 없다면 악용 인센티브가 약함.
설계 의도(이탈 방지)를 명확히 하고 별도 보상 구조를 만들지 않으면 자연 해결.

## 4. 공격형 목표의 무용 — 전원 생존형으로 수렴

**기획서 주장**: 공격형(105%) 성공 시 뱃지만 부여하여 금전 독식 방지.

### 왜 뚫리는가

| 선택 | 성공 보상 | 실패 패널티 |
|------|----------|------------|
| 생존형 (95%) | 없음 | -2,500원 |
| 공격형 (105%) | 뱃지 | -2,500원 |
| 방어형 (75%) | 없음 | -1,250원 |

공격형은 리스크는 같고 금전 보상만 없다. 합리적 선택은 100% 생존형.

### 반론 (현재 미제시)

부동산 금융맨 집단에서 뱃지·명예의 가치를 과소평가하면 안 된다.
단, 뱃지만으로는 약하다는 지적은 유효하다.

### 최종 판정

🟡 **보완 권장** — 공격형 성공 누적 횟수를 명예의 전당 입성 요건에 연계하면 해결.
예: "공격형 연속 3회 성공 → 🔥 뱃지 승급 → 명예의 전당 후보 자격"

## 5. 결제 시스템 — iOS 앱스토어 정책 충돌

**기획서 주장**: 포인트 소진 시 1만원 재충전.

### 왜 뚫리는가

앱스토어 정책상 iOS 앱 내 "디지털 재화 구매"는 IAP(인앱결제) 의무이며,
애플은 30% 수수료를 가져간다. 외부 결제 유도는 앱 삭제 리스크.

### 반론

**앱스토어 공개 배포가 아닌 경우 IAP 규정 미적용.**
클럽 내부 운영용 앱으로 TestFlight 또는 MDM 배포라면 이 이슈는 존재하지 않는다.
계좌이체·카카오페이 링크로 운영진이 수동 지급하는 방식으로도 충분히 운영 가능.

### 최종 판정

🟢 **해당 없음** — 배포 방식에 따라 다르며, 클럽 내부 운영 맥락에서는 문제 없음.

## 6. 카톡 공유 버튼 — 실제 전송 여부 검증 불가

**기획서 주장**: 앱에서 카톡 공유 버튼 클릭 시 자동 +1점 적립.

### 왜 뚫리는가

카카오 SDK의 `shareToKakao`는 공유 다이얼로그를 여는 것이지 전송 보장이 아니다.
다이얼로그를 열고 취소해도 앱 입장에서는 이벤트가 동일하게 발생한다.

### 반론 (현재 미제시)

하루 Max 1점이라는 상한이 있으므로 악용해도 얻는 포인트가 미미하다.
소셜 포인트 자체가 월말 생존을 위한 소소한 보조 수단이라면 엄격한 검증 비용이
오히려 더 클 수 있다.

### 최종 판정

🟢 **수용 가능** — 1점/일 상한 구조에서 악용 이득이 작다. 현행 유지.
