> 2026-10-06 기능 문의에서 출발. 같이 나온 "남의 기록 알림(자극용)"은 §6 에 설계만 기록해두고
> 이번 범위에서는 만들지 않는다.

---

## 1. 무엇을 만드나

**클럽달력 탭의 달력 칸마다 그날의 운동 기록 숫자**를 찍는다. 그게 전부다.

- 히트맵(색 농도) ✗ — 과하다. 그리고 색 농도는 "안 한 날"을 시각적으로 도드라지게 만든다
- 마일리지·거리 같은 양 총합 ✗ — 과하다. 갯수만
- 날짜를 누르면 → 기존 **오늘운동 피드를 그 날짜로 재활용**해서 모달로 보여준다
- **사람 검색** → 같은 달력의 숫자가 그 사람 기록만으로 좁혀진다 (그 사람 달력으로 "전환"이 아니라 핀셋)
- **종목 필터** → 마찬가지로 숫자가 그 종목만으로 좁혀진다
- 두 필터는 동시에 걸린다 ("홍길동의 수영만")

### 왜 클럽달력 탭인가

사용자는 기능이 아니라 **보는 방식**으로 탭을 인식한다:

| 탭 | 보는 방식 |
|---|---|
| 마일리지 | 순위 |
| 오늘운동 | 목록 (하루) |
| 클럽달력 | **날짜 격자** (한 달) |

같은 운동 데이터를 세 가지 방식으로 본다. 마일리지 탭 서브탭으로 넣는 안(검색·필터를 복제 없이
공유)도 검토했으나, 사용자 멘탈모델과 어긋나 기각.

## 2. 클럽 기능 opt-in → opt-out

지금까지 클럽달력 탭은 `clubs.enabled_features` 에 `'calendar'` 가 있는 클럽에만 보였다
([클럽-탭-optin.md](클럽-탭-optin.md)). 14개 클럽 중 2개만 켜져 있었다.

opt-in 을 건 이유는 행사 기능이 소규모 클럽엔 노이즈였기 때문인데, 운동 갯수 격자는 모든
클럽에 의미가 있어 그 논리가 맞지 않는다. 그래서 **탭은 항상 보이고, 행사 기능도 기본 ON,
운영진이 끌 수만 있는 opt-out** 으로 바꿨다.

### 새 컬럼 `disabled_features` — "끈 것 목록"

`enabled_features` 기본값만 `'{calendar}'` 로 뒤집는 안은 기각. 그러면 **나중에 추가하는 기능이
기존 클럽에선 꺼진 채로 시작**해서 결국 opt-in 으로 되돌아간다. "끈 것 목록"을 저장해야 새 기능이
자동으로 켜진 상태로 시작한다.

```sql
ALTER TABLE public.clubs ADD COLUMN disabled_features text[] NOT NULL DEFAULT '{}';
```

- 전 클럽 `'{}'` = 아무것도 안 끔 = 전부 켜짐
- `enabled_features` 는 남겨둔다 (DEPRECATED 주석). 웹은 안 읽지만 네이티브가 읽을 가능성을 배제 못 함
- 판정 헬퍼: `isClubFeatureOn(club, key)` ([config/clubFeatures.ts](../../src/config/clubFeatures.ts))
- 클럽 설정의 섹션명 "탭 관리" → **"기능 관리"**, 항목 "클럽달력" → **"행사 기능"**

| | 행사 기능 끔 | 행사 기능 켬(기본) |
|---|---|---|
| 클럽달력 탭 | 보임 | 보임 |
| 날짜별 운동 숫자 · 필터 | 보임 | 보임 |
| 다가오는 행사 · 행사 점 · 행사 등록 | 안 보임 | 보임 |

## 3. 데이터 — 집계 기준은 "오늘운동 피드와 같게"

**달력 숫자를 누르면 그 날짜 피드가 열린다. 두 수가 다르면("달력엔 5인데 눌러보니 4개") 신뢰가 깨진다.**
그래서 처음 계획(`club_workout_mileage` + `show_mileage`)을 버리고 **피드(`getClubWorkoutFeed`)와
정확히 같은 규칙**으로 센다:

| 규칙 | 피드 | 달력 RPC |
|---|---|---|
| 출처 | `workouts` | `workouts` |
| 멤버 | `show_in_feed = true` | `show_in_feed = true` |
| 차단 | 내가 이 클럽에서 차단한 사람 제외 | 동일 (`app_user_id()` 기준) |
| 날짜 경계 | 브라우저 로컬(KST) 자정 | `AT TIME ZONE 'Asia/Seoul'` |

> 처음엔 `show_mileage`(마일리지 랭킹 opt-out)를 기준으로 잡았으나 틀렸다. 달력은 피드로
> 들어가는 입구라 피드의 opt-out(`show_in_feed`)을 따라야 한다.

```sql
get_club_workout_day_counts(p_club_id, p_start_date, p_end_date,
                            p_user_id DEFAULT NULL, p_category DEFAULT NULL)
  → (workout_date date, workout_count bigint)
```

한 달 1,300건+ 를 원본으로 내리면 PostgREST 1,000행 제한에 걸리므로 날짜당 한 행만 내린다.

### 실측 검증 (2026-09, "유산소의 모든것")

| 항목 | 결과 |
|---|---|
| RPC 월 합계 vs 피드 방식 직접 집계 | 1,318 = 1,318, **일별 불일치 0일** |
| 화면 달력 합계 | 1,318 |
| 9/2 칸 숫자 vs 눌렀을 때 피드 카드 | 59 = 59 |
| 종목 필터(달리기) | 869 |
| 사람+종목("야시 · 달리기") | 12일 13회, DB 교차검증 일치. 9/4 칸 2 → 시트 2건(둘 다 야시 달리기) |
| 시트 안 날짜 이동 | 필터 유지 (9/5 → 1건) |

## 4. 재사용

| 필요한 것 | 가져올 곳 |
|---|---|
| 날짜 격자 | `ClubCalendarTab` 의 `react-calendar` — `tileContent` 로 숫자만 추가 |
| 날짜 탭 시 피드 | `WorkoutFeed` — **이미 `selectedDate` 를 받는다** ("오늘"은 이름일 뿐 고정이 아님) |
| 사람 검색 | **`MemberPickerSheet`** — 바텀시트 규칙 준수 + 닉네임·실명 동시 검색 (곁다리: `default:색상` 아바타를 `<img src>` 로 넣어 깨지던 기존 버그 수정 — 148명 중 45명 아바타가 깨졌었다) |
| 종목 목록 | `Club.tsx` 의 `mileageCategoryOptions` 를 prop 으로 전달 (이미 로드돼 있음) |

마일리지 탭의 멤버 검색은 **복사하지 않는다** — `maxHeight: '80vh'` / `width: '92vw'` 라
CLAUDE.md 의 vh 금지 규칙 위반이다(Android WebView 에서 0 으로 계산돼 모달이 접힘).
`MemberPickerSheet` 는 이미 규칙대로 만들어져 있다.

종목 필터는 `<select>` 를 쓰지 않는다 — cardio-android WebView 에서 select 드롭다운이 조용히
실패한다. 마일리지 탭과 같은 커스텀 메뉴 방식.

### 날짜 탭 → 피드 모달

- 모달 안에서도 사람·종목 필터가 그대로 걸린다 (핀셋의 연장)
- 그날 행사가 있으면(행사 기능 켜진 클럽) 모달 상단에 행사 칩 → 누르면 기존 `EventDetailSheet`
- 좋아요/댓글은 모달 안 자체 상태로 처리 (오늘운동 탭의 캐시와 섞지 않는다)

## 6. 후속: 자극용 알림 (팔로우) — 설계만 기록

이번에 만들지 않는다. 달력을 써보고 필요성을 다시 판단.

### 왜 "전체 알림"이면 안 되는가 (실측)

| 클럽 | 인원 | 하루 평균 기록 | 최대 |
|---|---|---|---|
| 유산소의 모든것 | 148명 | **40.8건** | 58건 |
| 풀코스PJT | 17명 | 9.2건 | 16건 |

클럽원 전원 실시간 알림 = 메인 클럽 기준 **하루 41푸시**.

### 결정된 방향 — 팔로우

- **더보기에 "팔로우 관리" 메뉴 신설**
- 팔로우 대상은 **클럽 단위**. 같은 사람이라도 클럽이 다르면 별도 대상 (클럽마다 닉네임이 다를 수 있음)
- 따라서 **한 운동에 알림이 여러 번 울릴 수 있다** — 사용자가 알아서 정리 (중복 제거 안 함)

### ⚠️ 선행 필수 — 알림 종류별 on/off

지금 `users.push_muted` 는 **전역 토글 하나**다
([More.tsx](../../src/pages/More.tsx), [notification-inserted.ts](../../api/webhooks/notification-inserted.ts)).
팔로우 알림이 시끄러워서 끄면 **좋아요·댓글 알림까지 같이 죽는다** (현재 like 3,488 / comment 87건).

### 푸시 인프라는 이미 있음

`notifications` INSERT → `notification-inserted` webhook → FCM. `type` 에 새 값만 추가하면 된다.
현재 type 은 `like` / `comment` 뿐.
