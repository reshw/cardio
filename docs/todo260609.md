# 작업지시서 — 삼성브라우저/카카오 인앱브라우저 파일업로드 이슈 (2026-06-09)

## 현상

**환경**: Galaxy 기기 + Samsung Internet 브라우저 / KakaoTalk 인앱브라우저  
**정상 환경**: Galaxy 기기 + Chrome ✅ / iPhone Safari ✅ / PC Chrome ✅

**증상**:
운동기록 추가 → 숫자/날짜 입력 (step 3) → 📷 추가 버튼 → 갤러리 앱에서 사진 선택 → 앱으로 돌아오면 **페이지가 새로 마운트**됨 (step 1 또는 step 3으로 초기화, 사진은 미등록)

## 디버그 패널로 확인된 사실 (`?debug=1`)

```
MOUNT step=3 draft_img=NO    ← 첫 진입 (localStorage에서 복원)
PICKER open (btn)             ← 📷 추가 버튼 클릭됨
[갤러리 앱 전환]
MOUNT step=3 draft_img=NO    ← 새 시간으로 다시 마운트! onChange 없음
```

**결론**: 갤러리 앱이 열리는 순간 **Samsung Internet/KakaoTalk이 WebView 페이지를 kill**함.  
갤러리에서 사진 선택 후 돌아오면 앱이 **cold start**로 재시작 → `onChange` 이벤트가 **절대 발화하지 않음**.

### 적용된 workaround (부분적으로만 동작)
- `localStorage` draft 저장/복원 → step/값은 유지됨 (step=3으로 돌아옴)

## 핵심 질문 — 검토 요청사항

### Q1. 왜 Chrome은 괜찮고 Samsung Internet은 kill하나?
- Android에서 외부 앱(갤러리) 진입 시 Chrome은 WebView 프로세스를 메모리에 유지
- Samsung Internet / KakaoTalk WebView는 백그라운드 전환 시 프로세스를 kill
- 이게 맞는 진단인지, 또는 **다른 원인이 있는지** 확인 필요

### Q2. BrowserRouter popstate 가능성
`BrowserRouter` 사용 중. 갤러리 앱 전환 시 Android가 history state를 push/pop하면  
React Router가 `popstate`를 잡아 navigation 이벤트로 처리할 가능성.  
→ `HashRouter`로 교체하면 달라지는지 확인 가치 있음

### Q3. `capture` 속성 시도
```html
<input type="file" accept="image/*" capture="environment">
```
카메라를 브라우저 내부에서 열어 외부 앱 전환 없이 촬영 가능.  
갤러리 선택 불가하지만, 페이지 kill 없이 사진 첨부 가능할 수 있음.  
Samsung Internet에서도 inline camera를 여는지 확인 필요.

### Q4. `visibilitychange` + 파일 선택 재시도 패턴
```js
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'visible') {
    // 파일 input의 files를 다시 읽을 수 있는지 시도
  }
});
```
페이지가 살아있다면 visibility 복원 시점에 파일을 읽을 수 있는지 확인.  
(kill 시나리오라면 이것도 불가)

### Q5. beforeunload / pagehide 훅
```js
window.addEventListener('pagehide', (e) => {
  // persisted: true면 bfcache, false면 kill
  console.log('persisted:', e.persisted);
});
```
`e.persisted`가 false면 진짜 kill. true면 bfcache. 디버그 패널에 이 이벤트 추가해서 확인 가능.

### Q6. bfcache 비호환성 요소 점검
bfcache 복원이 실패하면 full reload 발생. 다음 요소들이 bfcache를 막을 수 있음:
- `unload` 이벤트 리스너 존재 여부
- 열려있는 IndexedDB 트랜잭션
- `Cache-Control: no-store` 헤더
- 현재 앱에 이런 요소가 있는지 확인

### Q7. Samsung Internet 전용 file input quirk
Samsung Internet은 `display: none` 상태의 file input에서 `onChange`가 발화하지 않는 케이스 존재.  
현재 `.file-input-hidden { display: none }` → `opacity: 0; position: absolute; width: 1px; height: 1px;`로 변경 시 차이 있는지 확인.  
(단, 9a49807에서 동일한 `display: none`으로 작동했다면 이건 아닐 가능성 높음)

## 시도했으나 효과 없었던 것들

| 시도 | 결과 |
|------|------|
| sessionStorage → localStorage 교체 | step/값 복원은 됨, 사진은 불가 |
| file input을 form 밖으로 이동 | Samsung Internet에서 더 악화 |
| `<label htmlFor>` 방식 | 동일하게 kill 발생 |
| imagePreview base64 localStorage 저장 | kill 시점 문제로 무의미 |
| `input[type=datetime-local]` 항상 form 안에 유지 | 미확인 (revert 전) |
| 9a49807 완전 복원 | 동일하게 step=1 초기화 확인 |
