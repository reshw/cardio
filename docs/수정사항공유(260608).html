🔩 기술 메모 (내부 아카이빙용 — 대외 비공개)
발생 커밋: 2c1328c — iOS WebView discard 대응을 위해 sessionStorage draft 저장/복원 로직을 추가한 시점부터 발생

버그 1 — "증빙사진첨부 필수" alert이 사진 선택 직후에 뜨는 현상
Android WebView 일부 버전은 <form> 내부에 있는 file input의 onChange가 발생할 때 form의 submit 이벤트를 함께 spurious하게 발생시킨다. 이 시점에 proofImage React state는 아직 null(setState는 비동기 배치)이므로 handleSubmit의 검증 분기에서 "사진 미첨부"로 잘못 판단하여 alert가 발생했다. 이 alert 핸들러 안에서 fileInputRef.current?.click()을 다시 호출하던 로직도 있어서, 파일 픽커가 재오픈 → 유저가 back → popstate 발생 → 컴포넌트 재마운트로 이어지는 사이클을 만들기도 했다.

버그 2 — 사진 선택 후 종목 선택 화면(step 1)으로 돌아가는 현상
Android Chrome은 파일 픽커 Activity가 열릴 때 브라우저 히스토리에 내부 엔트리를 추가하고, 파일 선택 완료 또는 취소 시 이를 pop하며 popstate 이벤트를 발생시킨다. BrowserRouter(React Router)가 이를 받아 컴포넌트를 재마운트할 수 있다. 재마운트 시 sessionStorage draft를 읽어 step을 복원하는데, draft 저장이 비동기 useEffect 기반이라 파일 픽커가 열리기 직전 상태가 sessionStorage에 아직 반영되지 않은 경우 stale한 step 값(최악의 경우 step: 1)이 복원되는 타이밍 문제가 발생했다.

수정 방법 (4가지)
① file input을 <form> 밖으로 이동 — form과의 연관을 끊어 spurious submit 이벤트 자체를 차단. 핵심 수정.
② proofImageRef(useRef) 추가 — handleImageChange에서 ref를 동기적으로 업데이트. submit 검증 시 state 대신 ref를 사용하여 React 배치 업데이트 딜레이를 우회.
③ openFilePicker() 헬퍼 추가 — 파일 픽커 오픈 직전에 saveDraftNow()로 sessionStorage에 현재 상태를 동기적으로 즉시 저장. popstate로 인한 재마운트 시에도 최신 step이 보장됨.
④ handleSubmit에서 fileInputRef.current?.click() 제거 — 사진 미첨부 alert 후 자동 파일 픽커 재오픈을 제거하여 back 버튼→popstate→재마운트 사이클 차단.
